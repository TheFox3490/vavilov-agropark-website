# Центр агроробототехники и VR/AR технологий — сайт

Сайт Центра агроробототехники и VR/AR технологий Вавиловского университета.
Свёрстан по макету Figma, поднимается одной командой через Docker Compose.

**Стек:** React 19 + Vite (фронтенд) · Flask + SQLAlchemy (бэкенд) · PostgreSQL 18 · nginx

---

## Быстрый старт

```bash
cp .env.example .env
```

Заполни в `.env` как минимум четыре поля (ключи удобно сгенерировать через `openssl rand -hex 32`):

| Переменная | Что это |
|---|---|
| `POSTGRES_PASSWORD` | пароль базы данных |
| `SECRET_KEY` | ключ подписи сессий и ссылок из писем |
| `ADMIN_EMAIL` | почта первого администратора |
| `ADMIN_PASSWORD` | его пароль |

Затем:

```bash
docker compose up -d
```

Сайт поднимется на `http://localhost:8080`. Миграции накатятся, категории новостей
и учётка администратора создадутся автоматически при первом старте.

## Развёртывание на сервере

Наружу торчит **один порт** — им управляет переменная `HTTP_PORT` (по умолчанию 8080).
База данных порт не открывает вообще, она доступна только внутри сети Compose.

1. Скопируй папку проекта на сервер
2. Заполни `.env`, обязательно указав:
   - `PUBLIC_BASE_URL=https://твой-домен.ру` — на нём держатся ссылки из писем,
     адреса в карте сайта и карточки ссылок в мессенджерах. Оставишь localhost —
     Telegram и ВКонтакте будут показывать битую картинку
   - `JWT_COOKIE_SECURE=true` — раз сайт работает по https
3. `docker compose up -d`
4. Настрой внешний nginx проксировать домен на `127.0.0.1:8080`, там же выпусти
   сертификат (например, через certbot)

Примерный блок для внешнего nginx:

```nginx
server {
    server_name твой-домен.ру;
    client_max_body_size 12m;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

TLS и HSTS намеренно оставлены внешнему прокси — внутренний nginx их не трогает.

## Резервные копии

Копируется только то, что нельзя восстановить из репозитория: содержимое базы
(новости, проекты, услуги, состав центра, заявки, настройки, учётные записи)
и картинки, загруженные через админку. Изображения из макета лежат в образе,
код — в репозитории.

```bash
tools/backup.sh
```

Копия ложится в `backups/<дата-время>/`: дамп базы, архив загрузок и опись —
в ней видно, сколько чего внутри, без разворачивания. Старые копии удаляются
автоматически, по умолчанию хранятся четырнадцать последних (`--keep 30`).

Посмотреть, что есть, и восстановить:

```bash
tools/restore.sh
```

```bash
tools/restore.sh последняя
```

Восстановление затирает текущие данные, поэтому **перед разворачиванием копии
скрипт снимает страховочную** — если развернули не ту, вернуться есть куда.
Имя страховочной он печатает в конце.

Раз в сутки ночью — строка в cron на сервере:

```
0 4 * * * cd /путь/к/проекту && tools/backup.sh --quiet --keep 30
```

Копии лежат рядом с проектом, то есть на том же диске. Это спасает от
испорченных данных и неудачного обновления, но не от потери самого сервера —
папку `backups/` стоит забирать куда-то ещё, хотя бы `rsync` раз в неделю.

## Почта

Свой почтовый сервер не нужен: подойдёт любой внешний SMTP. Реквизиты задаются
в `.env` (`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`).

| Провайдер | Хост | Порт | Режим |
|---|---|---|---|
| Gmail | `smtp.gmail.com` | 587 | TLS, нужен пароль приложения (требует 2FA) |
| Яндекс 360 | `smtp.yandex.ru` | 465 | SSL |
| Mail.ru | `smtp.mail.ru` | 465 | SSL |

Пока `SMTP_HOST` пустой, письма не отправляются, а пишутся в лог — сайт при этом
работает штатно. В таком режиме держи `REQUIRE_EMAIL_CONFIRMATION=false`,
иначе зарегистрированный пользователь не сможет войти.

Заявки с формы обратной связи **всегда** сохраняются в базе и видны в админке;
письмо на `CONTACT_NOTIFY_TO` — дополнительное уведомление, и сбой почты
отправку формы не ломает.

## Как называется университет

Официально — **Саратовский государственный университет генетики,
биотехнологии и инженерии имени Н.И. Вавилова**. Прежнее «СГАУ им. Вавилова»
устарело, а «ВавГУ» — сокращение, которым университет себя не называет,
поэтому в коде его нет.

Где что используется:

| Место | Название |
|---|---|
| Логотип, заголовок вкладки, письма | Вавиловский университет |
| Политика и согласие на обработку данных | полное официальное |

В правовых документах нужно полное: там речь об операторе персональных
данных. В заголовке страницы — короткое, иначе он не помещается в поисковую
выдачу целиком (сейчас 68 символов). Полное название лежит одной константой
`UNIVERSITY` в `backend/app/settings.py`.

## Личный кабинет и пароли

Имя в шапке ведёт на `/account`: там видно, кто вошёл, и там же меняется
пароль. Раньше сменить его можно было только восстановлением по почте —
а на новом сервере почта может быть ещё не настроена, и админ оставался
с паролем из `.env` навсегда.

Текущий пароль спрашивается обязательно: открытой сессии для смены мало.
Сессия при этом не обрывается — токен выдаётся заново, из админки
не выкидывает. На ручку стоит ограничитель в десять обращений в час,
чтобы через неё нельзя было подбирать текущий пароль.

Если пароль забыт совсем, остаётся прежний путь — восстановление по почте
(нужен настроенный SMTP) или команда `flask create-admin` на сервере.

## Роли и доступ

- **Гость** — смотрит все страницы, отправляет форму обратной связи
- **Пользователь** — то же плюс личная учётка
- **Администратор** — раздел `/admin`: новости, проекты, услуги, состав центра,
  настройки сайта и заявки. Число необработанных обращений висит значком
  рядом со ссылкой на админку — на любой странице, чтобы заявку заметили
  до того, как о ней вспомнят.
  Плюс форма добавления новости прямо в сетке на странице «Новости», как в макете

Токены доступа лежат в httpOnly-cookie, их не достать из JavaScript.
Запросы на изменение защищены CSRF-токеном, пароли хранятся в виде argon2-хешей.

## Отступления от макета

Дизайнер — художник, а не разработчик, поэтому часть служебной логики в макете
не прорисована. Закрыто следующим образом (все места помечены в коде комментарием
`ОТСТУПЛЕНИЕ ОТ МАКЕТА`):

| Что в макете | Что сделано |
|---|---|
| В форме регистрации нет поля почты, но экран успеха просит проверить письмо | Добавлено поле email — иначе не работают ни подтверждение, ни восстановление пароля |
| Есть ссылка «Забыли пароль?», но экранов восстановления нет | Сделан стандартный поток: письмо со ссылкой → страница нового пароля |
| В форме добавления новости нет поля заголовка, хотя в модалке заголовок есть | Заголовок добавлен и сделан обязательным |
| Нет экранов редактирования и удаления новостей | Сделаны в разделе `/admin`, вместе с заменой картинки |
| Раздела админки нет вовсе | Спроектирован в той же тёмной эстетике |
| Ссылки на политику и согласие есть, текстов нет | Тексты-рыбы с верной структурой, правятся в админке — формулировки утверждает университет |
| Контакты нарисованы прямо в подвале | Вынесены в настройки, меняются из админки |
| У кнопок «Перейти к стартапу» нет адресов | Адрес задаётся у проекта; пока он пуст, кнопка ведёт на форму связи |
| Стартапы и услуги нарисованы статичными списками | Две сущности в базе, ведутся из админки |
| Экранов отдельного проекта и услуги нет | Сделаны на `/startups/<адрес>` и `/services/<адрес>` из тех же блоков |
| Карусель проектов на первом экране статична, карточки никуда не ведут | Карточки из базы, каждая ведёт на свой проект |
| Блок «Наши проекты» на главной — три статичные фотографии | Карусель по проектам из базы: центральная ведёт на страницу проекта, боковые встают в центр |
| На «Контактах» одна карточка руководителя | Карусель всего состава центра, редактируемая из админки |

## Проекты и услуги

Страницы «Наши стартапы» и «Наши услуги» устроены одинаково: список карточек,
у каждой своя страница с галереей, порядок и публикация — из админки, вкладки
«Проекты» и «Услуги». У карточки есть название, краткое описание для списка,
полный текст, главная картинка, галерея дополнительных кадров и необязательная
ссылка. Тип («Платформа», «Приложение», «VR тренажёр») есть только у проектов —
в макете подпись над названием нарисована лишь там.

Разделы разные, а механика общая, поэтому она не продублирована: на бэкенде
поля вынесены в примесь `CatalogItem`, а пять ручек CRUD заводит общая функция
`_register_catalog`; на фронтенде списки, страницы карточек и вкладки админки
собирают компоненты `CatalogList`, `CatalogDetail` и `AdminCatalog`. Различия —
это подписи и адрес раздела, они передаются настройками.

Таблицы всё-таки две, а не одна с признаком раздела: у проекта есть поля
карусели первого экрана, которых у услуги нет, а адреса живут в своих
пространствах имён — одинаковый `slug` в разных разделах конфликтовать
не должен, и это проверено.

Галерея на странице карточки устроена как в интернет-магазине: крупный кадр
и лента миниатюр под ним, нажатие на миниатюру ставит её в крупный кадр.
Главная картинка — первая в этой же ленте. Кадры показываются целиком,
без обрезки по краям: в галерею кладут в том числе скриншоты. Нажатие
на крупный кадр открывает его во весь экран — иначе мелкий текст
на скриншоте с телефона не разобрать.

Поле «главная картинка» — общий компонент `CoverField`: он же стоит в форме
новости, поэтому картинку у новости можно заменить или убрать после публикации.
Превью намеренно маленькое и с фиксированной высотой — иначе обложка занимала
почти всю модалку и выдавливала остальные поля.

Полноэкранный просмотр — собственный компонент `Lightbox`, а не общая модалка
для статей: у той липкая панель, отступы и своя прокрутка, из-за чего кадр
не помещался в окно и увеличение теряло смысл. Здесь кадр вписывается в экран
при любом размере окна и любой пропорции картинки, прокрутки нет.

Адрес страницы складывается из названия («Вектор-Сервис» →
`/startups/vektor-servis`) и остаётся доступным для правки. После публикации
его лучше не менять: внешние ссылки перестанут работать.

Один проект показывается сразу в нескольких местах сайта, поэтому «где
показывать» — это галочки, а не отдельные списки: страница «Наши стартапы»,
блок «Наши проекты» на главной и карусель первого экрана. Порядок общий,
задаётся стрелками в списке проектов.

## Карусель на первом экране

Восемь карточек из макета — это не то же самое, что список стартапов:
пересечение всего три позиции. Пять карточек заведены проектами только
для карусели — у них есть название, тип и кадр, но нет описания, поэтому
в список «Наши стартапы» они не попадают. Как только центр напишет текст
и поставит галочку, проект появится и там.

У карточки своё короткое имя (`card_title`) и свой кадр (`card_image_url`):
«VR TEHNUM» в узкую карточку не влезает, а в макете у Технума в карусели
трактор, тогда как на странице стартапов — человек в шлеме.

Кадр ищется по цепочке: свой → главная картинка проекта → первый снимок
галереи. Ничего нет — карточка остаётся тёмной плашкой с номером и названием,
подпись лежит на градиенте и читается без фотографии. Цепочка считается
на сервере (`Project.card_image`): в списке проектов галерея не передаётся,
и на странице до неё было бы не дотянуться.

Номера `01…08` считаются от позиции. Храни мы их в базе, после удаления
проекта в нумерации осталась бы дыра.

Пока карточки едут из базы, место под них держится пустым: высота первого
экрана выверена по пикселям, и без брони страница дёргалась бы при каждом
заходе. Если в карусели не отмечен ни один проект, блок исчезает совсем,
и первый экран просто становится ниже — проверено набором `hero-fit`.

### Вес кадров

Кадры карусели из макета весили 4.7 МБ на восемь карточек при слоте 295×200 —
самая тяжёлая тянула полтора мегабайта на первом же экране. Скрипт
`tools/bake_cards.py` ужимает их в WebP до 301 КБ, в 16 раз легче. Прозрачность
сохраняется: у кадров предмет вырезан, и сквозь фон просвечивает карточка
вместе с фотографией первого экрана.

Кадры, загруженные через админку, ужимаются на сохранении проекта, а не
на загрузке файла: тогда и кадр, выбранный из галереи, становится лёгким,
а сам снимок в галерее остаётся в полном размере.

Пережатие чужих файлов — место, где легко получить сюрприз, поэтому оно
обложено проверками, каждая из которых закрывает найденный на практике случай:

- **анимация не трогается** — пересохранение гифки в WebP оставило бы один кадр;
- **поворот из EXIF применяется явно** — телефон пишет снимок как есть, а поворот
  кладёт в тег; браузер его уважает, а пересохранение теряет, и вертикальное
  фото ложилось набок;
- **цветовой профиль переносится** — без него Adobe RGB выцветает,
  а Display P3 перенасыщается;
- **прозрачность сохраняется** — в том числе у палитровых PNG, где она задана
  отдельным полем, а не альфа-каналом;
- **копия оставляется только если она легче исходника** — у простой графики
  с прозрачностью PNG выигрывает у WebP (проверено: 4.4 КБ против 9.7 КБ);
- **любая ошибка не ломает сохранение** — показывается исходный файл.

Сам исходник при этом всегда остаётся на диске: копия для карточки лежит
рядом с суффиксом `--card.webp`. Остальные загрузки формат не меняют вовсе —
им хватает ограничения в 2400 px по большей стороне.

## Вес картинок

Из Figma всё выгрузилось в исходном разрешении, и это дорого обходилось:
главная тянула 3.6 МБ, из них фотография проекта — 1.4 МБ при слоте 531×366,
фон первого экрана — 1.1 МБ. Скрипт `tools/bake_media.py` пережимает картинки
макета в WebP под их настоящие места на странице: фон первого экрана до 1920 px
по ширине, обложки до 1600 (они открываются во весь экран из галереи), новости
до 1400, фотография сотрудника до 900. Обрезки нет — кадрирует браузер.

| | Было | Стало |
|---|---|---|
| Главная | 3.6 МБ | 641 КБ |
| Услуги | — | 559 КБ |
| Новости | — | 486 КБ |
| Стартапы | — | 338 КБ |

Исходники из макета лежат в `figma-export/media-sources` и `card-sources`
и в образ фронтенда не попадают: папка `frontend/public/media` похудела
с 14 МБ до 1.9 МБ. Пережать заново — `tools/bake_media.py` и `bake_cards.py`.

Сама папка `figma-export` весит 350 МБ и **в репозиторий не входит** — там
полноразмерная выгрузка макета. Сайту она не нужна: в репозитории лежат уже
пережатые картинки. Понадобится, только если захочется пережать их иначе, —
тогда выгрузку нужно взять из исходного проекта или получить заново
скриптами `tools/figma_*.py`.

Картинки, которые центр загружает сам, этим скриптом не затрагиваются:
при загрузке они ужимаются до 2400 px по большей стороне, а для карточки
карусели дополнительно готовится лёгкая копия.

## Блок «Наши проекты» на главной

В макете это три статичные фотографии: крупная в центре и две «на фоне».
Здесь то же самое, но живое — в центре текущий проект, нажатие ведёт на его
страницу, нажатие на боковую карточку ставит её в центр. Под карточкой точки:
на широком экране они показывают, сколько всего проектов, а на узком боковые
карточки скрыты — втроём они дали бы полоски по 60 px, в которых ничего
не разобрать.

Листать можно четырьмя способами: боковыми карточками, точками, стрелками
на клавиатуре и **смахиванием** — на телефоне это основной жест. Смахивание
слушает события указателя, поэтому работает и пальцем, и мышью. Порог
в 45 px и сравнение с вертикальным сдвигом не дают обычной прокрутке
переключать карточки, а клик после смахивания подавляется — иначе палец
улетал бы на страницу проекта вместо листания.

Пропорции сняты с макета: центральная карточка горизонтальная (1.45:1),
боковые — 1.4:1 и примерно вдвое меньше по площади, ряд занимает ширину панели
целиком. Потолок высоты (`min(52vh, 26rem)`) вступает в дело только на низком
окне: тогда ряд уменьшается целиком, оставаясь симметричным.

Набор проверок следит и за симметрией: зазоры слева и справа должны совпадать,
а центральная карточка — быть шире боковых. Это не теория: когда высота
ограничивалась через `max-height`, браузер пересчитывал ширину по пропорции,
карточка переставала заполнять колонку, прижималась к её левому краю
и оказывалась уже боковых — блок выглядел сломанным.

Какие проекты сюда попадают, решает галочка «Показывать в блоке „Наши
проекты“ на главной» в карточке проекта.

При первом запуске в базу заводятся четыре стартапа и пять услуг из макета —
с теми же текстами и фотографиями. Дальше центр правит их в админке.

## Поиск и ссылки

Telegram, ВКонтакте и поисковые роботы **не выполняют JavaScript**: что бы
приложение ни выставило в заголовок после загрузки, робот видит только тот
HTML, который пришёл с сервера. Поэтому голову страницы собирает бэкенд
(`app/api/meta.py`), а nginx вклеивает её в `index.html` директивой SSI:

```
<!--#include virtual="/api/meta?path=$request_uri" -->
```

Отдельного рендеринга, дополнительных контейнеров и сборочных шагов это
не требует — разворачивание остаётся прежним, `docker compose up -d`.
Если бэкенд не ответит, nginx вставит пустоту: страница откроется,
метатеги не появятся, ломаться нечему.

У каждой страницы свой заголовок, описание, картинка карточки и canonical.
Для новости, проекта и услуги они берутся из базы, так что после правки
в админке карточка ссылки обновляется сама (кэш — минута).

`/robots.txt` и `/sitemap.xml` тоже собираются бэкендом: карта сайта знает
про каждую опубликованную новость, проект и услугу, личные разделы закрыты
от индексации. Заголовок вкладки при переходах внутри сайта обновляет
приложение — хук `usePageTitle`.

**У новостей появились собственные адреса** — `/news/<номер>`. Раньше новость
открывалась поверх ленты без адреса: поделиться ссылкой было нельзя, а робот
видел только общий список. Теперь адрес меняется, а сама лента при этом
не перематывается наверх.

## Настройки сайта

Вкладка «Сайт» в админке. Две группы:

**Контакты центра** — телефон, почта, Telegram, ВКонтакте, адрес, график работы.
Показываются в шапке, в подвале и на странице «Контакты», адрес заодно задаёт
точку на карте проезда. Пустая ссылка на соцсеть значит «у центра её нет» —
иконка просто не появляется, а не ведёт в никуда.

Тексты новостей, проектов, услуг и документов набираются в одинаковых полях:
высотой примерно в пятнадцать строк и шрифтом помельче — чтобы на экран
помещался кусок, который можно вычитать, а не три строки с прокруткой.
Пустая строка разделяет абзацы, и они сохраняются на странице как есть.

**Правовые документы** — заголовок и текст политики конфиденциальности
и согласия на обработку данных. Разметка нарочно простейшая: строка,
начинающаяся с `## `, становится заголовком раздела, пустая строка разделяет
абзацы. Полноценный редактор здесь был бы из пушки по воробьям — документа
два и меняют их раз в год, — зато простой текст нельзя сломать до
неузнаваемости, и через него не вставить чужую разметку. Галочка внизу
убирает пометку «документ носит предварительный характер», когда университет
утвердит формулировки.

Хранится это в таблице `settings` как «ключ — значение». Список ключей вместе
со значениями по умолчанию лежит в `backend/app/settings.py`: чистая база сразу
отдаёт осмысленный сайт, а добавить настройку — одна строка в словаре,
без миграции. Неизвестные ключи запрос молча игнорирует, так что форма может
присылать себя целиком.

Контакты нужны на каждой странице, поэтому те же значения по умолчанию
продублированы в `SettingsContext`: пока ответ сервера в пути, подвал
не перестраивается на глазах.

## Состав центра

Карточки сотрудников на странице «Контакты» ведутся в админке, вкладка
«Состав центра»: фотография, должность, телефон, почта, Telegram, ВКонтакте.
Порядок карточек задаётся стрелками в списке, скрыть сотрудника можно
галочкой «Показывать на сайте».

Имя хранится по частям, и **отчество необязательно**: среди сотрудников есть
студенты, которым отчество указывать неуместно. Если поле пустое, на сайте
выводится «Фамилия Имя», иначе «Фамилия Имя Отчество».

При первом запуске в состав добавляется руководитель центра из макета.

## Что осталось доделать

Все 45 изображений макета выгружены и разложены по местам. Соответствие
«картинка → место на странице» проверялось визуально, а не по именам слоёв:
имена в макете неинформативные — `imgHawaii 1` стоит и на фотографии
руководителя, и на снимке VR-лаборатории. Семнадцать картинок, которые сайту
нужны в работе, пережаты в WebP и лежат в `frontend/public/media`; остальные
остались только в исходниках `figma-export/media-sources`.

Осталось со стороны заказчика:

- **Тексты услуг** — в макете у четырёх из пяти услуг продублирован один и тот же
  абзац про лазерную резку. Перенесён как есть; настоящие описания центр
  вписывает сам в админке, вкладка «Услуги».
- **Ссылки на стартапы и соцсети** — в макете заглушки. И то и другое теперь
  задаётся в админке: адрес стартапа в карточке проекта, соцсети во вкладке «Сайт».
- **Юридические тексты** — политика конфиденциальности и согласие на обработку
  персональных данных сейчас рыба. Формулировки утверждает университет,
  вписываются во вкладке «Сайт» без правки кода.

Из необязательного остался слайдер «Мы предлагаем» на главной: `OFFER_SLIDES`
в `src/media.js` содержит все четыре кадра из макета, а показывается только
первый. Пролистывание можно добавить отдельно.
